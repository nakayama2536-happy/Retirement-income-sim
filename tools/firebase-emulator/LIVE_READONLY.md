# Firebase実接続・読取り専用診断（未実行）

対象：Draft PR #28。ユーザーの実Firebaseプロジェクトに対し、本人ログインとFireStore **getDocFromServer** だけを確認する。データ作成、上書き、削除、個人バックアップの取込み、暗号化同期の開始は行わない。

## 実行方法（ユーザーPC上、本人の明示操作）
1. GitHub Draftブランチからこの `live-readonly.html` だけをPCに保存する。ソースコードは公開用の一般的な診断ツールであり、実アカウント情報を含まない。
2. ファイルのあるフォルダで `python -m http.server 8765 --bind 127.0.0.1` を実行する。Pythonがなければ別途ローカルサーバーを用意する。ファイルを直接 `file://` で開かない。
3. `http://127.0.0.1:8765/live-readonly.html` を開く。Firebase ConsoleのWebアプリConfigから4つの公開設定をコピーし、本人が管理するメールアドレスとパスワードをPCのこの画面にだけ入力する。パスワードやUIDをGitHub、ChatGPT、スクリーンショットへ載せない。
4. 「本人としてログインし、同期文書を読取り確認」を一度押す。結果は**エラーコードだけ**または成功/文書なし。パスワード入力欄はクリアし、セッションはメモリのみ、終了時にsignOutする。
5. 結果が「認証成功・Firestore読取り許可。同期文書は未作成です」なら読み取りゲートは通過。ただし**他ユーザー拒否、実Firestore書込み、CAS、iPhone/PC同期は未検証**。実UIDのルール一致と実文書の存在を個人情報なしで切り分けられる。
6. 結果が「文書が既に存在します」なら**即停止**。現状のデータを変更しない。原因確認と既存文書の保護を優先する。
7. 完了後ローカルサーバーをCtrl+Cで終了。保存したHTMLは削除してもよいが、Firebase Consoleやブラウザの個人データは削除しない。

## 注意
- GitHub Pagesへの公開やmainマージは不要。端末の個人保存データに触れない。
- 読取り専用診断でも、本人アカウントへの認証とクラウドのgetが発生する。利用者本人の認証操作は代行できない。
- この診断でパスワードが安全に管理されることを保証するものではない。PC上のローカル専用環境でのみ実行し、ブラウザ拡張や不審なプログラムのない端末を使う。
- 実Firestoreの書込み試験は、既存の `current` を占有し、Rulesでdeleteが禁止されるため**この診断では絶対に行わない**。専用の隔離テスト先と安全な片付け方を確認してから別工程とする。
