# ③-Bバックアップ確認の画面復帰対応（技術記録）

確認日：2026-10-25。対象：ロック復帰版の③-B競合解決。元の資産・計算条件・クラウド方式は変更しない。

## 問題の再現と原因候補

iPhoneで③-B-1の一括JSONを作成し、保存先を確認するため一時的にアプリを離れて戻ると、Web Locksの編集権限再取得前に同期パネルのfocus/visibleイベントで自動更新が動き、権限不在をSTOPと解釈して確認済みバックアップのダイジェストとチェック欄の操作権限を無効化していた。再現は架空データのイベント模擬に基づき、本人端末での全要因は未確定。

## 修正

同期パネルの自動起動トリガーに、現在画面が表示中かつ現在の編集Web Lockを保有することを追加条件とする。編集中の別画面から権限を奪わず、いったん保存したバックアップ確認状態を単なる復帰途中のロック不在で取り消さない。独立した手動操作③-Bは、二段階同意、端末・クラウド世代・暗号化・保存競合の全検証を引き続き実行する。

## 検証の境界

架空データの再現テスト：バックアップ→非表示→復帰→チェック欄再有効→明示操作まで。実ブラウザの2端末統合テスト：同じ操作順をWebKit/Chromiumを使って確認する。Github CI、配布一致、端末実機確認は別々の根拠とする。端末の保存領域やFirebaseデータを直接操作しない。
