# 配置・更新メモ v0.9

## GitHub中心の運用
2026-10-04以降、公開アプリの正本はGitHubの `main` とする。

基本フロー:
1. GPT/開発者は `main` から作業ブランチを作成する。
2. コード・仕様を作業ブランチで更新する。
3. Pull Requestを作成する。
4. GitHub Actionsで構文、計算回帰、CSV回帰、公開データ混入を自動確認する。
5. UI・実機・個人設定を伴う確認だけを人が実施する。
6. 問題がなければ `main` へ反映する。

通常の開発ではGitHub DesktopやVS Codeの手動操作を必須としない。ローカル環境は、画面確認・実機検証・緊急時の復旧に使用する。

## 自動確認
`.github/workflows/ci.yml` で以下を自動実行する。

- JavaScript / MJSの構文確認
- `test_calc.mjs` の計算回帰テスト
- `test_csv_export.mjs` のCSV回帰テスト
- Private GitHubまたはGitHub外へ置くべきファイルが公開リポジトリに混入していないことの確認

CIが失敗した変更は、そのまま `main` へ反映しない。

## GitHubへ置いてよいもの
公開リポジトリ `Retirement-income-sim` には以下のみ置く。

- HTML / CSS / JavaScript
- PWA設定
- 公開技術仕様
- 匿名化したテストデータ
- 個人値を含まないテンプレート
- 変更履歴
- CI設定

## GitHubへ置かないもの
公開リポジトリには以下を置かない。

- 個人設定JSON
- 個人用要求仕様書
- 保留事項台帳
- 個人基準検証
- アプリから出力したバックアップJSON / CSV
- 年金通知画像、口座・契約番号、税務原本、医療情報
- パスワード、APIキー、PAT、秘密鍵

整理済み個人データはPrivate GitHub、高機密原本はGitHub外で管理する。

## リリース前の人による確認
自動テストで代替できない以下だけを人が確認する。

1. GitHub Pages等の公開画面が意図した表示になっていること。
2. iPhone/PC等の対象端末で個人設定JSONを読み込めること。
3. 「整合性チェック」でエラー0件であること。
4. 95歳末資産、管理基準、iDeCo/DC見込、年金開始月など主要値が個人基準検証と整合すること。
5. 個人情報が公開画面・公開リポジトリへ出ていないこと。

## 更新前後のバックアップ
個人設定を変更する場合は、Private側の正本とアプリ出力バックアップの整合を確認する。

v0.2〜v0.8の端末内設定はv0.9へ移行可能だが、年次設定から月次設定へ変わるため、個人設定JSONの再読込を推奨する。
