## 目的・維持する条件

ブラウザ内の正本 `lifeplan-sim-state-v1` は維持し、設定済みの計算式・管理予算・比較案・CSVを変更しない。GitHub Pagesを維持し、Firebaseは**別途承認後に非公開同期先としてだけ**利用する。
統合状態の全体JSONを暗号化したものだけをクラウドへ送り、個人金額やバックアップ、暗号化合言葉、ログイン用パスワード、実利用者UIDを公開GitHubに入れない。

## 同期の手順と保護
1. 本人がFirebase Consoleで所有する専用プロジェクトを作成し、Email/Password認証とFirestoreを設定。Authに本人だけを作成し、`github.io`の公開アプリのドメインを必要に応じてAuthの許可ドメインへ登録する。Cloud Firestore Rulesは `docs/firebase-sync-firestore.rules.example` のテンプレートを**実UIDに合わせてFirebase Console側で**登録・テストする。テンプレート内のUIDプレースホルダーは安全のため拒否設定。Rulesを無認証で許可しない。
2. 利用中のiPhone・PCのそれぞれで**更新前の一括バックアップ**を取得し、別の安全な保存先へ確保。初回のデータ優先元は本人が選ぶ。同じアプリのSafariとホーム画面アプリが異なる保存領域なら別々に判定する。個人JSONをGitHubへアップロードしない。
3. Firebase Web API key・authDomain・projectId・appIdを端末上で入力。これら公開Web設定だけを端末内に保存可能であり、秘密のログインパスワードと暗号化用合言葉は保存しない。本人のメールアドレスとパスワードでログインし、端末間で共通の**16文字以上の暗号化用合言葉**で解除する。合言葉を忘れると暗号化済みデータを復元できないため、GitHubとは別の安全な場所で本人管理する。
4. 初回クラウドが空の場合、本人の**明示的な「この端末を初回の同期元にする」**操作だけで暗号化して登録する。クラウド既存の場合、まず内容を復号して開始日・開始資産・比較案数・差分の有無を表示し、本人が**明示的なクラウド取込**を選択する。初回はどちらかを自動優先しない。
5. 登録後、アプリを開きログイン・暗号化ロック解除済みでオンラインの場合、約30秒ごと・保存後・前面復帰時に同期チェックする。Firestoreのオンライン専用トランザクションでクラウド世代の一致を検査し、古い端末による上書きを防ぐ。両端末で別々の変更があれば**競合として停止**。オフライン時は端末の保存を維持し、次回オンラインで照合する。Cloud Firestoreの一般的なオフライン最終書込み優先機能は今回使わない。
6. クラウドだけ変更され端末が前回同期以降変更されていない場合、復号・データ互換・計算可能性を検証し、元の統合状態を端末内 `lifeplan-private-sync-previous-v1` に保持してから原子的に反映する。画面内に未保存入力がある疑いがある場合は自動取込を止め、内容の再確認と明示取込を求める。現在の基準をそのまま使い回して採用しない。
7. 「同期を停止してログアウト」しても端末データ・比較案・旧バックアップは削除しない。ブラウザ保存領域を削除しない。手動一括バックアップは引き続き独立して必要。

## 暗号化・互換性
- ブラウザWeb CryptoのPBKDF2-SHA256（600,000反復、ランダム16-byte salt）から鍵を導出し、AES-256-GCM（ランダム12-byte IV）で端末側暗号化。クラウドに送るのはversion、revision、暗号化payload、暗号文ダイジェスト、ownerUidなど必要な同期メタデータだけ。Firebase管理者は暗号化済み内容を保有し、操作日時やUID等のメタデータは扱う。
- 500,000バイトを超える平文または725,000バイトを超える暗号化payloadは**同期停止**、既存データとバックアップを残す。現行版では分割アップロード未実装。Firestoreの1 MiB制限を超えて無言で保存しない。
- 統合 `config` / `scenarios` と互換フィールド、将来未知のトップレベルデータを一体として移す。年金など未採用下書き、端末固有の認証情報・ローカル鍵・キャッシュ・クラウド同期設定は同期対象外。端末間自動同期ができても、一括バックアップの代わりにはしない。
- AuthセッションはFirebase SDKの端末ブラウザ保存を利用。暗号化合言葉はアプリ終了後に自動解除しない（再入力が必要）。したがってアプリを閉じている間や、鍵未解除では同期されない。初期実装の制限として明示する。
- 既存端末のSafari/ホーム画面とPCでは保存領域が異なる可能性がある。自動同期を開始しても古い履歴や端末固有の未採用入力を無断統合しない。

## 重大な制限・未検証
- Firebaseの実プロジェクト作成・Auth権限設定・Firestore Rules反映、セキュリティRulesエミュレータ検証、Web SDKの外部CDN実ロード、iPhone Safari/PWAの本人認証・安定性、PCブラウザとの実データ連携は**未実施**。
- Nodeや隔離Chromiumで架空状態を用いた検証は、実クラウドのデプロイや権限設定の証拠ではない。
- 旧端末の戻し方は、更新前に別保存したバックアップとアプリ版の組を確認し、同期中の状態の自動上書きで過去版へ戻そうとしない。
- Cloud Firestoreの無料枠・課金・データ保管地域・本人の長期運用・合言葉管理を実環境導入前に確認する。暗号鍵が失われたときの復旧可能性を本人と確認する。
- 本Draftの作成はGitHub mainへの反映、GitHub Pages本番公開、本人データのクラウド初回アップロード・自動採用の許可ではない。
