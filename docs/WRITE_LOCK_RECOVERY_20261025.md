# iPhoneの編集ロック復帰・競合取込み停止の修正候補（未公開）

確認日: 2026-10-25。起点: 公開 `e62e23910c6eb902629ba11acee8a550981759a4`。本人のiPhoneで12:12、12:34の二度、③-Bが「別画面が編集中、または同時更新制御を利用できない」として停止した。本人データに対する取込完了の証拠はない。

**原因候補と検証の境界:** `write-access.mjs` は `pagehide` で編集ロックを解除するが、起動時 `acquireWriteAccess()` が返す `writable` は固定値のため、ボタン表示と保存時 `assertWriteAccess()` が異なる場合がある。iOS実機でどのイベントが起きたか、Web Locksが競合しているか/利用不可かは未確認。

**今回の変更:** 現在の保有状態をgetterで返し、`pagehide`・`visibilitychange:hidden` 時にロックを解放する。`pageshow` と可視復帰時は、以前の要求終了を待ち、`ifAvailable:true` で再取得する。取得不可/競合時は読み取り専用のままで、UIに理由を表示する。監視コールバックはUI描画だけを更新し、保存やクラウド上書きは実行しない。

**維持:** ロックを強制取得しない。localStorageによる擬似ロックを追加しない。暗号化、Firebase、計算式、比較案、同期競合停止、バックアップ/採用値に変更なし。

**検証:** Nodeでロック初回・遷移後再取得・別画面占有・Web Locks利用不可・保留中・取得失敗・非表示復帰を検証。既存のCIとクラウドUI/コメント、2端末実ブラウザ/更新・復旧/100歳末回帰を再確認してから本番公開を別承認とする。実機で解消する保証はしない。
