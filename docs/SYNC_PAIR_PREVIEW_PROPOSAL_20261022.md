# PC→iPhone架空暗号文の実機受渡し：専用プレビュー候補

確認日：2026-10-22（日本時間）。開発対象：Draft PR #28（feature/fb-single-user-sync-20261016）。
**状態：検証候補のみ。新しい公開承認、新プレビュー配信、実クラウド2端末受渡しは未実施。**

## 目的と境界
PCとiPhoneが、既存の無料検証プロジェクト lifeplan-sync-sandbox の同一の試験文書を別端末から安全に交換できるか確かめる。両端末が個別に12/12成功したことと、端末間の一連の受渡し成功は別の証拠。

- 使用データ：コードに固定した完全架空の受渡し用スナップショットのみ（開始資産1234万円、比較2案、未知フィールド）。
- 使用する暗号：同期Draftで採用した sync-crypto.mjs の AES-256-GCM、PBKDF2-SHA256。
- 書込み先：Sparkの lifeplan-sync-sandbox と sandbox/{検証UID}/snapshots/trial **のみ**。既存Rulesを変更しない。
- 通常アプリ、本人のブラウザ保存・一括バックアップ・計算、本人用Firebase lifeplan-private-sync、GitHub Pages、既存encrypted-mobile診断プレビューには触れない。
- 別チャンネル pair-check の配信は**未承認**。公開・期限設定・GitHub main反映・Auth許可ドメイン変更・課金・本人データ移行は実行しない。
- テスト用ログイン、UID、合言葉は端末内でのみ入力する。本人用の合言葉・実データを転用しない。バックアップ取込機能は設けない。

## 必須の安全条件
既存12/12試験の「削除・不存在確認済み」は利用者提供結果。新試験の前にもFirestoreサーバーから試験文書の不存在を確認する。既存文書があれば停止し、無断削除・上書きしない。

## テスト画面の操作（公開承認・配信後のみ）
1. **PC**：検証用HTTPSプレビューをクエリ文字列なしで直接開く。同じテストアカウントと架空試験専用16文字以上の合言葉を入力し、「① PCから試験データ送信」を1回。不存在条件付きで架空暗号文rev1を保存・読戻しする。
2. **iPhone Safari**：同じプレビュー、同じテストアカウントと同じ試験用合言葉で「② iPhoneで受信・確認応答」を1回。rev1を復号して架空データと比較し、確認応答を暗号化してrev2として保存する。
3. **元のPCの同じブラウザ**：テスト認証情報と合言葉を再入力し、「③ PCで確認・削除」。非秘密の端末内試験IDとrev2を復号照合した場合のみ限定削除し、サーバー上の不存在を確認する。
4. iPhoneの誤入力・通信失敗・途中終了では再送信や再応答を繰り返さない。PCの非秘密の未完了マーカーを保持する。未応答rev1だけは、内容を再照合してPCからの明示的な中止・限定削除が可能。対象が不明なら停止し、Firebase Consoleで状態を確認する。
5. 画面のサニタイズ済み結果だけを共有する。認証情報・UID・合言葉・JSON全文は共有しない。

ChatGPT等がURLに ?utm_source=... を付けると、厳格なオリジン検査により停止する。URLはSafari/Edgeへ直接入力する。**新URLは未配信のため未確定**。

## 完了条件と限界
- 自動試験：Chromium/WebKitの別ブラウザ環境と隔離した模擬クラウドで端末間の送信・受信・確認応答・削除・再起動を確認する。実サービス接続ではない。
- 実機試験：実PCとiPhone Safariから同じFirebase試験文書の rev1→rev2→削除・不存在を確認すれば「実クラウドの端末間架空暗号文受渡し確認」とする。
- **本アプリの設定・比較案・実績・採用条件の実機同期を確認したことにはならない。** その後、実アプリ候補を別の安全な環境で検証する工程が必要。本番化・本人データ移行を無断で進めない。

## 公開候補と実施境界
GitHub Actionsでは配信せず、許可リスト化した静的ファイル、SHA-256、CSP、no-store、noindex、権限・読取範囲を検証する。候補ZIPは pair-check-candidate-NO-DEPLOY。公開外の APPROVAL_REQUIRED.json に未承認を明記する。

次の公開には、別Hostingプレビューチャンネル pair-check、短期の新規公開期間、接続先・Authドメイン・現在のtrial不存在、現行Rules維持、停止・復旧方法の確認が必要。既存 encrypted-mobile の期限（前回CLIで2026-11-03 22:53:34 JST）は保持し、勝手に延長しない。Auth許可ドメインを自動変更しない。

プレビュー停止や期限切れはFirestore文書を消去しない。未公開なら候補は破棄するだけでよい。公開した場合もテストプレビューと試験文書だけを限定して扱い、本番アプリ・本人データ・バックアップを削除しない。
