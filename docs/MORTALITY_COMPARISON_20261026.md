# 死亡時期の比較（未反映）— 実装範囲と検証条件

状態：未公開の開発候補。対象版 `v0.9.7-mortality-review-20261026`。
基準は PR #36 の main `2ad53c729ceded3d8d5895aca5d8a4d5e8a3e4f6`、tree `98a70d6fc91d5b2e9f96fe41a58c91963f43f823`。

## 操作
「結果を見る → 死亡時期の比較（未反映）」で、本人または配偶者のいずれか一人の死亡想定月を選ぶ。
残された方自身の老齢基礎・老齢厚生・遺族厚生の差額を含む **公的年金合計の仮年額** を入力する。遺族年金だけを入力しない。死亡月まで元計画、翌月から指定年額÷12を計上する資金計画用の近似。
残された方の老齢年金開始前に死亡後の月が存在するときだけ、開始前と開始後の仮年額を別に指定する。死亡翌月が開始月なら前段階は不要。実際の請求日、隔月振込、未支給年金、受給資格、繰下げ制限は自動確定しない。

支出の正本は既存の管理予算。月次予算の仮配分割合（合計100％）と費目別倍率を編集する。食費0.7等は利用者の比較仮定で、公的統計から自動採用した数値ではない。初期配分は未配分100％、その倍率は常に1.0。不明な税社保・保険などを自動削減しない。「架空660万円モデル」は明示ボタンでのみ入力され、資産・年金・管理予算を変更しない。

「比較用の仮定」を確認して試算すると、死亡翌月の収支変化（同じ年月の基準案対比較案）、費目別月額、年齢期別の公的年金・全収入・管理予算支出・臨時支出・期末資産を表示する。死亡時一時費用は死亡月に1回だけ追加し、既存臨時支出とは別に扱う。入力変更や他の設定更新で古い試算を無効にする。

同じ画面で採用条件を保存した場合は、更新された条件で再試算できる。別画面の保存更新を検知した場合は古い基準条件の再使用を防ぐため、死亡比較の試算・参考年額転記・年月候補入力を再読み込みまで停止する。比較操作自体には編集権や保存を必要としない。

## 変更しないもの
採用設定、保存比較案、実績、バックアップ、同期データ、元の物価基準、計算期間方式、既存エンジンの運用順序、既存CSVを変更しない。試算の保存・採用・外部送信はない。下書きは再起動時に消える。

## 制度参考の範囲
参考式は65歳以上・受給権・請求・繰下げ影響を資料で確認済みのケースに限定。死亡者の報酬比例年額D、生存者の老齢厚生年額E、老齢基礎年額Bを用い、参考遺族厚生額=max(0.75D,0.5D+0.5E)、差額支給=max(参考遺族厚生額−E,0)、合計=B+E+差額。Dに死亡者の繰下げ加算を含めない。手入力した配分・年金額の制度適合性を認定するものではない。
公式情報確認日：2026-10-26。日本年金機構：
- https://www.nenkin.go.jp/service/jukyu/seido/izokunenkin/jukyu-yoken/20150424.html
- https://www.nenkin.go.jp/service/jukyu/seido/roureinenkin/kuriage-kurisage/20140421-02.html
所得税・社会保険の自動変更、加算・共済・遺族基礎年金の各条件、二人の死亡、資産相続、保険金、iDeCo死亡一時金、制度の将来変更は対象外。生存者が繰下げ中の参考式による自動転記は停止し、区間別仮年額でのみ比較する。

## 停止する条件
期間外死亡月、未入力、配分合計不一致、基準月次台帳の不整合、給与生活中の死亡後純入出金、帰属不明の失業給付・一時収入・夫婦合算労働収入、参考式の確認不足では停止する。負残高は資金枯渇の参考であり借入額ではない。

## 検証の区分
- Node：`node --test test_mortality_comparison.mjs`。実際の `runRetirementPlan` の月次台帳で切替・倍率・二重計上・基準データ保護を確認。
- DOM単体：架空文書と実計算モジュールを使用。アプリ全体・Service Worker・実保存の検証とは区別。
- フルアプリの実ブラウザ：`node tools/browser-test/mortality-ui-check.mjs`。Chromium/WebKitの独立コンテキスト・架空JSONだけで、保存不変、未消去の試算と入力の再起動、読取り専用画面、実storageイベント後の停止、最新条件での再試算を確認する。実行結果は対象headのActionsに記録し、未実行を合格にしない。
- PWA更新・復旧：別の `tools/browser-test/run-browser.mjs` で既存旧版のC1/C1-Rを保持し、PR #36から候補へのC2/C2-Rを追加。新死亡比較のUI試験ではService Workerを遮断するため、両者を別の証拠として扱う。
- 本人実機：公開後の別工程。個人JSONの再送・サイトデータ削除・クラウド上書きを自動で要求しない。
