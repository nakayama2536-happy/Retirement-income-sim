# 競合時だけクラウドを正本にする解決（開発候補／未公開）

対象：同期が初期登録済みの端末で、クラウド版が前回同期より新しく、かつ端末にも未送信の**保存済み**変更がある場合。既存③・自動同期の競合停止は維持し、③-Bだけを例外操作として追加する。

- ④の暗号化スナップショット復号・整合確認のあと、③-B-1でこの端末の現在の一括JSONをダウンロードする。ファイル保存を本人が確認後、端末の変更破棄への別の明示同意が必要。ダウンロードを開始したことは保存完了の証拠ではない。
- ③-Bでの操作前に、端末保存ダイジェストとクラウドrevision/digest、同期登録の同一性、書込権限、通信を再確認する。クラウドが同じrevisionで内容だけ変わった、あるいは巻戻された場合は危険なので停止する。
- クラウドのデータ形式・暗号化・本人条件・互換性の検証後、もう一度クラウドrevision/digestを照合する。端末置換前に既存の直前状態保全処理で保護し、atomicな保存APIで置き換える。
- 読込みだけでクラウドのcompare-and-swapを呼ばない。復元直後の全体状態・マーカーを整合させ、④の一致を確認する。
- 未保存入力、他タブの操作、認証失効、バックアップ作成失敗、保存失敗、合言葉不一致、同時変更では停止する。
- 検証は完全架空データを用い、Firebase本番データには一切アクセスしない。本番公開・本人データ変更は別途明示的な承認を要する。
