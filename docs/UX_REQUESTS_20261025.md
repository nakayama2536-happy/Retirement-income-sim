## 死亡想定年月（添付シート5）：**計算機能は未実装**

名称案：「本人が亡くなる想定年月（任意）」「配偶者が亡くなる想定年月（任意）」。これは実際の寿命の見通しや医療上の予測ではなく、ライフプラン比較専用の**仮定**。本人と配偶者のそれぞれの年月は独立に指定可能とし、保存済み現在計画は変更せず、比較案と採用値を分ける。

以下が決まるまで金額計算と個人条件への反映は行わない：

1. 対象月の収入・生活費・公的年金/iDeCo・働く期間を、その月まで計上するか翌月から停止するか。既存の年月/年齢期との境界の整合。
2. 残された人の公的年金と遺族給付をどう推計するか。制度・所得・加入・年金選択に依存する部分は、本人が承認した外部原本と適用年の公的情報に基づく。未算定を0円と解釈しない。
3. 夫婦世帯と単身の管理予算を分けるか。食費・住居費・保険料・旅行・介護などを一律に半額としない。管理予算が支出正本である関係は維持。
4. 葬儀・臨時支出、生命保険・退職金・相続の受取、対象資産の帰属と相続税等の参考値、税/社会保険の扱いを個別に確認。複数経路で重ねて計上しない。
5. 本人死亡後も配偶者の計画を継続する場合の評価終了条件。比較の評価時点・価格基準・対象資産を共通にし、期末残高の意味を変えない。
6. 片方のみ死亡、順序が逆、同年月、計画範囲外、未設定、不正な日付、保存済み比較案への影響を区別する。

**次段階の最小案**：まず架空設定で「月次の死亡イベント」と「存命者の収入/予算入力が必要」という診断だけを追加し、未確認制度額を自動生成せず試算を停止する。採用値への書込みはしない。本人の入力条件と承認仕様がそろった後、別工程として計算・画面・保存・CSVの受入を行う。この候補へ日付欄だけを追加するのは誤解を招くため行わない。

## 試験と完了境界

- 既存資産計算・保存・復元・CSVを変更せず、原則としてDOM・CSS・表示文言だけを修正。ただし同期番号については案内文字列とその試験の期待表示を同時更新する。
- 架空データのNode回帰、構文、配布manifest、390pxと1280pxの静的描画を確認。GitHub Actionsでの実アプリ操作・クラウド競合・更新失敗の回帰は、開発PRへ登録する場合に必須。
- **公開/main/Pages、Firebase実データ、本人採用設定、比較案・バックアップ・端末保存領域への操作なし**。本候補はまだ公開済みではない。PR作成、マージ、公開はその具体的な操作範囲の承認を確認して行う。
- 失敗・旧版復旧：候補を採用しない場合は現行公開mainがそのまま利用できる。将来公開後に問題があれば当該UI差分のみRevertして同じGitHub Pagesへ戻す。本人のサイトデータ削除・旧JSON自動復元は行わず、旧版で新版入力の完全な復旧を保証しない。
